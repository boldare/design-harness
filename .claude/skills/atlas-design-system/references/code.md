# Code

React 18, TypeScript, CSS Modules, Vitest in browser mode (Playwright) with describe-me. Read two existing components before writing one (for example `src/components/Switch` and `src/components/TextField`) and match them exactly.

## Files
- Component: `src/components/<Name>/<Name>.tsx`, `<Name>.module.css`, `<Name>.test.tsx`, `index.ts`, and an export in `src/index.ts`.
- Screen: `src/screens/<Name>/` with the same files; mockup frame sizes live in the test helpers (`src/test/PhoneFrame.tsx`), not in CSS.

## CSS
- Only `var(--…)` from `src/styles/tokens.css` (generated by `npm run tokens`; never edit it). Allowed literals: `0`, `100%`, `50%`, `none`, `transparent`, `1` for flex, `inherit`, `currentColor` and keywords.
- Focus: `:focus-visible { box-shadow: var(--shadow-focus); }`.
- Disabled: `opacity: var(--opacity-disabled)` on the root.
- Runtime values: a value the component computes from its props while it runs (a thumb position, a filled fraction) is set inline as a custom property named `--rt-<name>` and read in CSS with `var(--rt-<name>)`. It is not a token and never stands in for one. The Claude Design build allows the `--rt-` prefix and nothing else that is not a token.

## Tests are the stories
describe-me records every test as a story: `render` from `vitest-browser-react` records a frame, each interaction records one more, `step()` from `@describe-me/vitest` names one. The viewer shows them, and Live mounts the test for real.
- `describe('<Name>')` with one `it('<state>')` per state in the README, named exactly as there (`default`, `focus`, `error`, …). `npm run check-states` compares the specs with the recorded tests: it reads the first column of the States table, or the backticked names in the first sentence of the States section, so a note such as "No `error` state" belongs in a later sentence. A state with an axis (checked × state) renders both values side by side in one test, in `layout.row` from `src/test/layout.module.css`.
- Each test asserts what the README promises for that state: roles and names, `aria-invalid` and the message (`toHaveAccessibleDescription`), `aria-busy`, disabled, focus (`userEvent.tab()` then `toHaveFocus()`). It ends with `await expectAccessible()` from `src/test/a11y.ts`, which runs axe in both themes. Behaviour beyond the states (a flow through a screen, a toggle) gets its own tests. Realistic copy from the spec, never lorem ipsum.
- Controlled components keep local state in a `Controlled<Name>` wrapper defined in the test file. Never pass a registered component (such as a Link) in the props of such a wrapper: describe-me would name the test after it. Make it inside the wrapper instead.
- Screens render with `{ wrapper: PhoneFrame }` and answer requests with `respond()` from `src/test/respond.ts`. Both are browser-only, so Live runs them too.
- Recorded frames show `:focus-visible` and `:hover` as the browser had them: a `focus` state ends on `userEvent.tab()`, a hover state on `userEvent.hover()` as the test's last pointer gesture (a click after it ends the hover). Do not fake them with classes or data attributes.
- Text matchers: `toHaveTextContent` is exact in Vitest; use `toMatchTextContent(/…/)` for a part of the text.
- A throwaway test (for example one that takes screenshots to check a screen by eye) is fine while working, but remove it and its output before the report. Leave only the tests the spec asks for.

## Checks (all must pass before the report)
```
npm run tokens
npm run lint:tokens      # rejects raw values in component, screen and test CSS
npm run typecheck
npm test                 # the tests, the stories and axe in both themes; writes .describe-me/
npm run check-states     # every state in a spec has a test of that name
```
`npm run check` runs the last four.

## The viewer
`npm run dev` runs the tests in watch mode and the describe-me viewer on port 6006: Foundations read from `tokens.css` (light and dark), every test as a story, Live to interact with a component or screen, and the background switch for the dark variant. `npm run docs` builds the static site with Live into `describe-me-dist/`. The viewer repaints after each test run, so a file saved halfway only fails one run.
